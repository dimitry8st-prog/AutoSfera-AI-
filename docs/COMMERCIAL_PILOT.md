# AutoSfera AI — коммерческий пилот 2.1

## Назначение

AutoSfera AI — мультиагентная платформа для одного автосалона. Она автоматизирует первичную консультацию, поддержку клиентов, сервисные обращения и поиск внутренних регламентов сотрудниками.

Рабочий слоган: **«Единый интеллект автодилера»**.

## Что уже в 2.1.0

- четыре агента и 17 skills, LangGraph-оркестратор, TF-IDF fallback и опциональный pgvector/HNSW RAG, mock/OpenAI LLM;
- роли `admin` / `sales` / `service` / `employee`, постоянные сессии, кабинет заявок;
- PostgreSQL как основное хранилище пилота, SQLite — локальный fallback;
- Alembic-миграции, Docker Compose, `/health` и `/ready`;
- исследования конкурентов с human approval;
- Action Gateway: ИИ только предлагает тест-драйв или сервис, сотрудник подтверждает выполнение;
- n8n sandbox без доступа к таблицам приложения.

Каталог, заказы и контакты в Knowledge Base — **демо-данные**, пока салон не подставит свой прайс.

## Границы закрытой беты (один салон)

Входят:

1. Sales Agent — подбор автомобиля, кредит, лизинг, Trade-in и предложение тест-драйва.
2. Customer Support Agent — статусы тестовых заказов, документы и FAQ.
3. Service Agent — гарантия, ТО и предложение записи в сервис.
4. Employee Agent — регламенты, скрипты и эскалация руководителю.
5. Web-чат, HTTP API, журнал диалогов.
6. Action Gateway + демонстрационная CRM (`requests`).
7. Базовая аналитика обращений, эскалаций и заявок.

Не входят в подтверждённый production-контур беты: корпоративный IdP, живая CRM/DMS, Telegram Bot API, активированный и откалиброванный pgvector, загрузка документов через интерфейс, юридически значимые решения ИИ.

## Масштабирование

Каждая запись диалога, заявки и действия содержит `dealer_id`. В пилоте используется `main-salon`. При переходе к сети добавляются таблицы дилеров, филиалов и пользователей без смены публичных бизнес-моделей API.

## API пилота

| Метод | Endpoint | Назначение |
|---|---|---|
| `POST` | `/api/chat` | Диалог с оркестратором и агентами |
| `POST` | `/api/auth/token` | Демо-вход сотрудника |
| `POST` | `/api/requests` | Создание лида / заявки (демо-CRM) |
| `GET`/`PATCH` | `/api/requests` | Воронка заявок салона |
| `GET` | `/api/analytics/summary` | Сводные показатели салона |
| `GET` | `/api/knowledge` | Просмотр демо-базы знаний |
| `GET`/`POST` | `/api/actions*` | Очередь Action Gateway, review, retry, callback |
| `GET` | `/health` | Состояние платформы |
| `GET` | `/ready` | Готовность PostgreSQL или SQLite |

## Критерии готовности пилота (выполнены)

- четыре типа обращений корректно маршрутизируются;
- диалоги не теряются после обработки API;
- заявки изолированы по `dealer_id`;
- аналитика считается из сохранённых данных;
- отсутствие данных приводит к безопасной эскалации;
- автоматические тесты проходят полностью;
- демо запускается без внешнего LLM в `LLM_MODE=mock`.

## Критерии закрытой беты

- секреты AUTH/ACTION/POSTGRES ротированы, CORS ограничен доменом пилота;
- staging на PostgreSQL, backup/restore прогнан;
- тест-драйв и сервис создаются только после approve роли;
- 12 сценариев приёмки пройдены сотрудником салона;
- в UI явно видно, что каталог демо, пока не загружен прайс салона.
