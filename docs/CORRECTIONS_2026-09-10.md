# Коррекционные дополнения AutoSfera AI

**Дата документа:** 10.09.2026  
**Контур:** Action Gateway  
**Статус:** реализовано и подготовлено к объединению после успешной проверки CI

## 1. Назначение документа

Документ фиксирует изменения, внесённые в AutoSfera AI при переходе от прямого создания заявок из диалога к контролируемому выполнению внешних действий. Он дополняет основную техническую документацию и позволяет проверить, что именно изменилось, почему это было необходимо и какие ограничения остаются.

## 2. Причина корректировки

Ранее чат мог сразу создать тест-драйв или сервисное обращение. Для демонстрации это удобно, но для рабочего контура недостаточно безопасно: отсутствовало независимое подтверждение сотрудником, а повторный запрос или неопределённый результат внешней интеграции могли привести к дублированию действия.

После корректировки AI только предлагает действие. Выполнение начинается после проверки роли и явного подтверждения человеком.

## 4. Жизненный цикл действия

1. Пользователь запрашивает тест-драйв или сервисную запись.
2. LangGraph и профильный агент формируют предложение действия.
3. Action Gateway сохраняет его со статусом `waiting_approval`.
4. Сотрудник с подходящей ролью подтверждает или отклоняет предложение.
5. Подтверждённое действие атомарно получает исполнитель.
6. В режиме `mock` результат записывается в демонстрационную CRM; в режиме `n8n` подписанный запрос отправляется в настроенный webhook.
7. Результат и переходы статусов фиксируются в `action_events` и операционных логах.

Подробный контракт API, статусы и настройка описаны в [`ACTION_GATEWAY.md`](ACTION_GATEWAY.md).

## 6. Конфигурация

| Переменная | Назначение |
|---|---|
| `ACTION_GATEWAY_MODE` | `mock` для демонстрационной CRM или `n8n` для внешнего исполнителя |
| `ACTION_WEBHOOK_URL` | URL production-webhook n8n |
| `ACTION_WEBHOOK_SECRET` | отдельный секрет HMAC-подписи Action Gateway |
| `DATABASE_URL` | PostgreSQL для пилота; при отсутствии используется локальный SQLite fallback |

Секреты запрещено хранить в Git. Перед внешним развёртыванием демонстрационные значения необходимо заменить.

## 7. Что намеренно не изменено

- FastAPI остаётся единой точкой входа.
- LangGraph остаётся центральным оркестратором.
- Существующие агенты, Skills, RAG и Knowledge Base сохранены.
- SQLite сохранён для автономной разработки и тестов.
- PostgreSQL остаётся основным хранилищем пилотного серверного контура.

## 8. Оставшиеся ограничения

- Реальная CRM/DMS пока не подключена; режим `mock` использует собственную демонстрационную CRM.
- n8n workflow поставляется выключенным и требует URL, секрета и настройки целевой системы.
- Production end-to-end проверка с реальной CRM и реальным экземпляром n8n не выполнялась.
- Статус `delivery_unknown` требует ручной сверки с внешней системой перед повторным запуском.
- Production-развёртывание, мониторинг инфраструктуры и регламент дежурств находятся вне текущего изменения.

## 9. Следующий контролируемый этап

Поднять тестовый экземпляр n8n, настроить секреты вне репозитория, подключить один sandbox-адаптер внешней системы и выполнить end-to-end проверку: предложение → подтверждение → webhook → callback → запись результата → сверка аудита. Только после этого переключать отдельный пилотный процесс с `mock` на `n8n`.

## 10. Дополнение от 10.09.2026 — воспроизводимый n8n sandbox

Добавлены отдельный Compose-контур `compose.n8n-sandbox.yaml`, автоматическая генерация локальных секретов, импорт и активация тестового workflow, а также smoke-тест полного HTTP-цикла. n8n публикуется только на `127.0.0.1`, не получает доступ к PostgreSQL и общается с AutoSfera исключительно через подписанные webhook-запросы.

Реальная CRM/DMS по-прежнему не подключена: sandbox возвращает тестовый внешний идентификатор выполнения n8n. Переключение production-процесса разрешается только после успешного запуска smoke-теста на машине с Docker и настройки выбранного CRM/DMS API.
